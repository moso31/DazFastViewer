## 模板点的统一行为

| 图形 | 含义 | 单击与拖动 |
|---|---|---|
| 实心圆 | 一个节点的参数入口 | 左键单击选择部位；左右键拖动分别使用该点的横纵映射。某个工具通道可能实际控制配套 Twist 骨，不能只凭点名决定写入对象。 |
| 虚线圈圆点 | 多节点联动组 | 左键单击选中该控制组并高亮成员；拖动按各成员独立的属性、sign、size 同步修改。它不是固定点标记，也不自动变成 IK。 |
| 菱形 | 属性控制点 | Body 中两点分别为 Translate Hip 和 Translate Figure；按模板中的平移参数操作。 |
| 三角 | 模板跳转 | 左键单击切页；左右键四方向拖动均不改姿态。Head 左上 Face 入口禁用，提示“本阶段不支持 Face”；Template 下拉列表也不含 Face。 |

鼠标按下时保存目标身份、初始参数和鼠标位置。小于 3 个逻辑像素的移动仍视作单击；超过阈值才进入拖动，捕获该次鼠标按键。斜向拖动同时应用横、纵两个映射；某一方向未绑定时只使用另一个方向。左右键同时按下时保持最先按下的模式，第二键不切换当前手势。

拖动计算相对于按下时的原值，不在每帧重复累加同一位移。达到限位后停止；反向移动按起点公式返回。Shift 拖动拟采用 0.1 倍精调，倍率在按下时确定；普通滚轮不调姿态。Esc、窗口失焦、角色切换、场景卸载均取消本次拖动并恢复按下时的值。

右键按下时延迟菜单：超过阈值就执行右键拖动，松开后不弹菜单；未拖动松开才显示点菜单。菜单项目固定为下表，不把右键拖动保留给相机。

| 点菜单项目 | 适用点 | 左键选择后的结果 | 右键／四方向拖动 |
|---|---|---|---|
| 定位到参数 | 单节点、属性、节点组 | 定位到目标部位的参数；组列出成员 | 无姿态变化 |
| 恢复加载时的本点参数 | 有有效绑定的点 | 只恢复此点实际绑定参数在场景加载时的值；组为一次提交，不恢复未绑定的 Morph | 无额外拖动动作 |
| 固定位置（IK） | 单节点且已有 IK 链 | 切换 008 的位置固定，记住开启时的世界位置 | 无额外拖动动作 |
| 固定角度（IK） | 单节点且已有 IK 链 | 独立切换 008 的角度固定，记住开启时的世界朝向 | 无额外拖动动作 |

固定状态以额外的小锁标记显示，不改变原来虚线组点的含义。原有视口 IK 仍是移动末端的入口；本轮三个模板的标准拖动遵循官方参数映射。不能把手腕圆点的左键动作擅自替换成屏幕平面 IK。总体规范中的 IK Effector 通过已有视口入口与同一固定状态联动；若后续要增加模板内专门的 IK 手柄，应单列交互预案。

固定约束的预案：只在 IK 及髋部带约束移动中求解；普通 FK 参数点保持其参数映射，不偷偷改动另一条骨链以抵消编辑。固定点是后续 IK 的约束目标，并非所有 FK 参数的锁。此项须在人工核对时明确接受，避免把它误解成 DAZ ActivePose 行为。

## 位置、方向和灵敏度

坐标和全部八方向表见[逐点清单](interaction-map.md)。Body 为 B01–B36，Hands 为 H01–H44，Head 为 N01–N05。坐标不含窗口边框／Source／Controls，不随截图显示尺寸变化。

参数值增减使用 DAZ 原生通道空间。转动角色或改变相机，不交换控制点的横纵含义。`XTranslate` 等使用目标节点父级空间；只有父变换为单位矩阵时才能直接当作世界轴。不能把“角色左侧”与“屏幕左侧”混写。

手指近节靠近掌部，末节靠近指尖；图中两只手均为手背示意，左上为角色左手，右下为角色右手。零姿态下，四指左手 Z 负向、右手 Z 正向通常为屈曲；拇指使用 Y 屈伸轴，不能统一按 Z 处理。

`size` 在 DXE 中是鼠标映射的量程参数，不是角度。显式值包括 200、400、700、800、7500、10000；未写出的暂按 DAZ 默认 300 记录。[DAZ 官方变更记录](https://docs.daz3d.com/public/software/dazstudio/4/change_log_4_10_0_123)记载编辑器将默认 -1 解释为 300。实际“像素／角度”关系仍须定量核对，不能直接使用 `size` 度／像素。

拟实现公式为 `目标值 = 按下值 + 位移 × sign × 通道量程 / size`，再遵守该参数的限位。这里的鼠标位移以逻辑像素计；通道量程及未限位通道的处理须通过 DAZ 中 20／50 像素拖动记录确认。模板缩放不再次乘入参数增量。手指各轴的范围不同，不能用一个统一角速度代替模板映射。

## 必须优先人工核对的差异

1. **头部总方向**：先核对 B01／N01 左键上下是否抬头／低头、左右是否转头，右键上下是否同样屈伸。用一次基准核对排除整个表的鼠标总符号误差。
2. **两种手腕入口的差异**：Body 的 Left Hand 右键纵向为 `zrot / pos`；Hands 的 `lHand` 右键纵向为 `zrot / neg`。原文件确实相反；预案保留差异，不能为了一致性自动统一。
3. **整手与拇指组差异**：Left Hand Group 的拇指纵向为 `yRot / pos / 800`，Left Thumb Curl 为 `yRot / neg / 默认 300`；右手同样相反。以原模板为准分别核对，不让整手握拳与单拇指操作共享错误符号。
4. **拆分骨工具通道**：上臂 X、大腿 Y、前臂 X 的基础 Bend 节点通道可能锁定，但 DAZ PowerPose 使用工具旋转访问器。表中给出了 Twist 骨候选，尚未通过动态 API 证实；实现前必须确认，不能以“锁定”为由删掉这些动作。
5. **组标签与成员绑定**：手臂组的显示标签写 Twist／Bend，但成员使用 `secondRot`、`thirdRot`、`firstRot`。先依据各骨的 rotation_order 解释，并再解析工具代理；不能把标签当作实际参数名。
6. **双眼右键**：N02 的右键水平对两眼施加相反 Y 旋转，形成对眼／分眼；右键纵向未绑定。左右单眼点仅绑定左键横纵，不补造右键动作。
7. **平移菱形**：B21 和 B35 左键横纵是 X／Z；右键横纵是 X／负 Y。左键纵向改变深度、右键纵向改变高度，不是两键都在屏幕平面移动。
8. **Head 的 Neck 名称**：DXE 使用 `Neck`，基础 DSF 为 `neck`／`neckLower`／`Neck Lower`。预案按原生 ID／名称别名匹配到下颈部，不自动把它扩成整个头颈组。

## 人工验证方法

1. 在 DAZ 中用 Genesis 8.1 Female 的默认姿态建立基准，记录所用模板名称、限位开关和显示缩放；避免直接在重要已摆好姿态的场景上累计试验。
2. 打开核对页，先验证上述重点项。选中对应点并查看 DAZ 的 Controls 四槽及参数值；每次只沿一个方向拖动，然后撤销回同一基准。
3. 每个姿态点分别做左键上、下、左、右，以及右键上、下、左、右，共 680 项。无绑定／锁定的项也应验证“不变化”；不要只验证可见动作。
4. 记录实际受影响参数、起止值与拖动距离。联动组尤其检查成员、两侧符号，以及未绑定部位是否被误改。
5. 在核对页填“一致／有差异”与备注，导出 JSON。也可按 `B20：右键向上实际……` 的格式直接反馈，或填写 CSV。浏览器中已填记录不是自动通过标记。
6. 另外核对导航不改姿态、右键单击与拖动分离、Face 禁用、限位、取消、角色切换与高 DPI 命中。

核对页是本地说明与记录工具，没有 3D 求值器；在图上点击只切换说明。真正动作的人工基准来自 DAZ，编辑器实现后的验收再按同一清单执行。

## 后续实现安排

人工验证后，把确认的映射固化为数据配置，保留节点点／节点组／属性点／导航点四种类型。加载阶段解析角色实例、骨骼别名、工具旋转代理、锁定和限位；场景 ID 优先于可改名的显示标签。Head 采用本轮五点范围，Face 在模板发现阶段就过滤。

Qt 图控件只产生姿势编辑命令。Runtime 复用 008 的输入版本隔离、灰模交互预览与松手提交路径；鼠标移动合并为最新值，松手提交一次完整 ERC／JCM／蒙皮／服装／发丝／碰撞／细分更新。预览不会每次重载 DXE，也不会在 UI 中直接改网格或 Cycles。

髋部带固定约束移动需要单独接入 008 的位置／朝向目标；角色整体平移与髋部局部位移保留不同身份。普通 FK、节点组和髋部求解必须在同一姿势事务中提交，取消时恢复完整起点。

DXE 解码目前作为离线研究工具即可，先生成项目自己的可审阅配置。正式运行时读取 DXE、长期维护不同插件版本或更广泛模板兼容，须作为明确的实现选择记录；当前没有将 DAZ DLL 或 Python 解码依赖接入编辑器。
