# DazFastViewer — A Faster, More Efficient Viewport Renderer for DAZ 3D

## 从源码构建

详细步骤见 [Windows 构建文档](Docs/build_windows_cn.md)，包含新机器准备、Visual Studio 2022 / 2026、自动依赖下载、手工安装、离线使用及故障排查。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\bootstrap.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build.ps1 -VisualStudio 2022 -Configuration Release
```

构建脚本会在工程根目录生成 **`DazFastViewer.sln`**；本机直接打开 `D:\DazFastViewer\DazFastViewer.sln`，选择 **Release / x64**，以 `DazFastViewer` 为启动项目按 F5。只生成解决方案可加 `-ConfigureOnly`，首次在 IDE 中构建时会自动整理启动依赖。

当前支持 Windows 10/11 x64、具有 AVX2/FMA/F16C 等指令集的 CPU，以及受 OptiX 9.1 支持的 NVIDIA GPU（建议 RTX 20/30/40/50 系列）；渲染需要 R590+ 驱动。支持单屏和多屏，普通启动使用主屏或已保存的位置。默认构建多架构 Release 运行包，程序位于 `out/vs2022/Release/DazFastViewer.exe`；分发时复制整个 `Release` 文件夹，目标机器无需安装 VS、Python、Qt 或 CUDA Toolkit。

首次准备后只需重复第二条构建命令。仅在本机开发、希望缩短内核编译时间时加 `-CudaArchitectures Auto`；分发前用默认 `Common` 重新构建。具体范围与验证限制见 [Windows 构建文档](Docs/build_windows_cn.md)。

## 我为什么要做这个东西

其实原因很简单，我自己用 DAZ 3D 用得比较多，但是一直觉得它的更新速度和使用体验在 4.24 以后越来越差，到 DAZ6 Iray 已经卡的没法用了。

我还记得曾几何时 DAZ 的 Viewport Iray 交互要更优秀的多，当年可以开着 Iray 也能让鼠标以相当流畅（至少10帧/s）的速度离线流畅渲染的。

这个问题从4.23以后让我难受了很多年，我也不是没跟官方论坛反馈过，写了个全英文的问题反馈到DAZ Forum，发邮件，人家也承认了这是个问题，但我就没看到他们修复。可能人家太忙了吧。

后来我就想，与其一直等官方慢慢研发，不如我自己从头做一个。至少可以先按照自己的需求来。

赞美AI时代。

## 这个项目想做什么

只关注一件事：提升 Iray viewport 的效率。

它是一个比较轻量、比较简单的 DAZ 场景查看和操作工具。把我原来在 DAZ 里面使用的角色、服装、道具和场景加载进来，然后可以在这个工具里直接预览、调整和操作。

简单来说，我希望它能够解决这样一个流程：

> 打开一个 DAZ 场景，然后快速看到它、调整它、摆一下姿势，再从不同角度预览它。

整个过程不需要太复杂，也不需要为了一个简单的预览操作，启动一整套很重的软件环境。

### 体积云

通过“创建 → 体积云”添加，在场景树选中云层后调节云底高度、厚度、密度、云量、云团大小和风向。时间只计算指定时刻，支持任意前后调整，不自动播放。云层及参数支持撤销、重做和 `.dufex` 保存重开。

碰撞对象列表默认按当前世界 AABB 体积从大到小排列；对象缩放或变形后，点击“按AABB重新排序”更新顺序。按钮保留勾选，不修改云参数或触发渲染重建，组按成员 AABB 的并集计算。

在“体积碰撞与穿透尾迹”中勾选陨石等大型对象或组，云洞会随其位置、形变和可见性更新。穿透速度指定尾迹方向和长度，不自动移动源对象；时间从 0 起形成尾迹，保留时长限制长度，恢复时间控制旧尾迹重新填云的速度。对象离开云层后，其后方的尾迹仍可穿过云层。碰撞由实际网格顶点生成低精度凸包，并沿运动方向扫掠；额外范围为 0 时不外扩，柔化只在边界内部过渡，设为 0 可关闭柔化。凸包会填平凹陷以及所选组成员之间的空隙，不计算逐三角面的流体动力学，也不累积交互操作的历史轨迹。

每层云使用 8 个顶点、12 个三角面和 GPU 程序化密度。默认采样预算 64，可调 16–192；最多勾选 16 个碰撞源，每个凸包至多 24 个顶点、48 个平面。几何凸包按网格缓存，形变时重建；刚体变换只更新平面，远离云层的碰撞体剔除。相机移动不重算碰撞，密度和时间修改不重建凸包或场景几何。碰撞采样成本随凸包数量和平面数增加，多个复杂角色及云内视角尤其耗时，应只勾选需要驱散的对象。降低采样预算和细节层数可减少视口开销；小型云洞或很薄的云层需要更高采样预算。云的透明边界盒不拦截视口对象选取，也不作为水体或物理系统中的实体障碍。

`CloudTest`、`CloudPanelTest` 分别验证碰撞与保存流程、实际 Qt 滚轮行为；`CloudRenderProbe` 验证 OptiX 图像与材质更新开销，编辑器 `--cloud-test` 验证菜单、时间编辑、撤销、重做和重开。离屏渲染耗时不代表大型场景视口帧率。

### 城市 PCG（首版）

“创建 → 城市 PCG…”打开独立面板。选择建筑 DUF 文件夹，点击“扫描建筑原型”，勾选原型并点击“生成 / 更新城市”。本机默认指向 `G:\G3\Environments\PhilW\Night and Day City\03 Buildings`，推荐初始使用 Building5、Building Tall2、Building Tall1，4 × 4 街区；也可以勾选全部 10 个建筑。扫描只读取目录顶层的模型 DUF，不把材质预设当成建筑。无需先制作 Blender 资源。

可设置种子、街区数量、每边地块数量、街区尺寸、道路宽度、填充率、原点和 LOD 距离。选择“新城市”可叠加另一座城市，选择已有城市则更新其配方。生成在后台完成，支持取消、移除、Ctrl+Z / Ctrl+Y；Ctrl+S 保存为 `.dufex`，重开时从原型和种子重建。源 DUF / DSF / 贴图保持只读，场景文件仍依赖原内容库。

LOD0 等于 LOD1。LOD1 共享导入网格，LOD2 实际移除窗框、空调等小结构并压缩顶点，LOD3 合并每个街区的大体块，LOD4 将最多 4 × 4 街区合为建筑轮廓贴合的平薄网格，通过浮点高度图作真实竖直置换，同时保留少量地标体块。LOD4 的基网格预先保留高度不连续处的边界，每栋普通建筑约 12 个三角形，不使用密集均匀细分；它是实验性高度代理，尚未烘焙完整立面颜色，也不是任意形状的连续城市高度场。高度缓存位于系统临时目录 `DazFastViewer/city-cache-v1`，重开配方可重新生成。

默认分界为 300 / 3000 / 30000 米，按相机到街区包围盒的距离、视场和视口尺寸修正，15% 滞回，相机停稳后切换。区域代理与其子街区互斥，保留阴影／反射需要的场外几何。可强制各档、隐藏城市、锁定当前自动档位；锁定在打开或重建文档时重新评估一次。面板显示实际启用的街区档位与实例展开／共享网格三角形数。首版上限 32 × 32 街区、20000 个候选地块；这不是帧率保证。

在材质面板选择城市或“城市共享材质”组，可直接修改各原型的共享材质，LOD1 / LOD2 的同类建筑统一更新；道路和人行道也使用现有材质系统。LOD3 / LOD4 使用轻量代理材质，不自动烘焙或同步原型全部着色效果。城市整体可使用场景组变换；首版的结构编辑应通过城市面板进行，暂不支持逐栋编辑、非规则道路、地形贴合、倒塌、踩踏或陨石坑。稳定的城市、街区、地块编号及独立生成配方为后续局部重建保留入口。

核心实现位于 `src/city`。`CityTest` 覆盖确定性、LOD、共享材质、保存／追加／删除；`CityRenderProbe` 是需 OptiX 的离屏置换与档位验证；编辑器 `--city-test` 验证实际面板生成、视口切换、撤销和重开。离屏结果不代表可见视口帧率。

### 在独立视口里预览

在场景树选中 **Environment Options → Environment → 夜景**，勾选 **是否启用夜景** 后使用日期驱动的日夜天空。它替代当前 HDRI；关闭后恢复原来的环境。原生 DAZ `.duf` 和没有夜景字段的旧文件默认关闭，`.dufex`、渲染设置文件及撤销／重做保留夜景参数。关闭时相关控件禁用；“仅场景”模式仍关闭环境照明。

快速预览银河可用 2024-07-06、当地时间 00:00、UTC 时差 0、纬度 30°、经度 0°，望向南方天空。夜景地面在白天曝光下会很暗，可降低 Exposure Value 或增加月亮／星空补光强度；“显示穹顶”仅控制相机背景，不关闭补光。

日期、当地时间、UTC 时差、经纬度沿用 `SS Day / SS Time` 系统。星空和银河随恒星时转动，包含 J2000 星表的岁差旋转；`Dome Rotation` 同时旋转太阳、月亮和星空，“星空附加旋转”只作恒星天球的艺术调整。星光随太阳落到地平线下 4°～18°逐渐显现，地平线附近有消光。月球位置包含主要轨道摄动及海平面观测者视差，月相和亮面方向由太阳位置决定；月亮强度、大小、颜色及大小变化时是否保持总光量均独立可调。这里不模拟地形遮挡、精密大气折射、月球表面地貌或月光的大气多次散射，也不声称与 Iray 绝对测光一致。

“星空分布”默认采用**网页式程序化星空**：按 [wcGSDy](https://www.shadertoy.com/view/wcGSDy) 的三维球状噪声生成远、近两层星光，每层包含三种尺度／亮度分布。星位使用固定 seed，调密度不会随机换一批位置；这是视觉星空，并非真实星座。“程序化星空密度”默认 1 对应网页，减小逐渐隐藏暗星，增大显示更多暗星。三维方向求值避免经纬撒点在极区聚集，远层星光受到银河尘埃吸收，近层保持白色。银河沿用网页的银心、晕光、偏蓝外围和两层尘埃吸收，还原红褐色云团及宽阔不规则暗带，没有上一版 fBm 的方向扭曲。网页轴向映射到 J2000 银河坐标，仍随日期与地点旋转；银河强度、对比度和星光强度独立可调。

选择**真实天文星表**可恢复 HYG 恒星位置和 B-V 色彩，此时“可见极限星等”生效，程序化密度不生效。目录来自 [HYG v4.1](https://github.com/astronexus/HYG-Database)，含 15,598 颗不暗于 7 等的恒星；真实恒星分布本身不均匀，银河附近较密。星位查询表保存每个区域最近的两颗恒星，按角距离绘制星核，查询表像素尺寸不决定星核精度；中档在星位中心覆盖 15,591 颗恒星，极密集多重星仍有近似。这里不是天文测光工具，也不自动模拟气象或光污染。

| 星空补光方式 | 行为与取舍 |
| --- | --- |
| 均色 | 用星空自然颜色的球面平均值补光，保留地平线与消光；非相机光线不保留星点。 |
| SH（默认） | 9 个 RGB 球谐系数保留低频方向性，负值截断；用于环境辐亮度，由 Cycles 继续计算材质、遮挡和反弹。非相机光线中的精细星点会被平滑。 |
| 完整环境 | 背景、模型照明和反射使用程序化星点与银河；仍只有一个背景光，完全不创建逐星点光源。小而亮的星点可能增加收敛所需采样。 |

月亮在三档中均保持独立的解析月盘与照明。为了保留场景遮挡，这里的 SH 不是直接给材质叠加无阴影自发光，也没有把已卷积的漫反射辐照度误当作入射环境再次积分。[Ramamoorthi 与 Hanrahan 的论文](https://graphics.stanford.edu/papers/envmap/)支持用低阶 SH 近似平滑环境补光；锐利反射仍需高频环境信息。

“夜空精细度”低／标准／高控制银河球状噪声的 2／4／5 层叠加，标准档与网页默认一致。原始 27 邻域搜索保留，只提前排除球支持区以外的候选；CPU 与 CUDA 共用一个模型，通过单个 SVM 节点执行，避免将循环展开成庞大着色图。程序化模式不使用星空／银河图片，也不分配 HYG 查询表；只有选择真实星表时，才使用 1K／2K／4K 两张查询表，约占 16／64／256 MiB。无需用 8K／16K 整张图片维持星空精度；程序化计算仍比查图片更费着色时间，可降低精细度并使用默认 SH 补光。

首次选用某档时准备 8,192 个球面补光样本，缓存球状噪声原值；调密度和对比度只对这些小样本求值，不重新做邻域搜索。时间、位置、强度、旋转和月亮调整不烘焙天空图片。Cycles 仍会更新背景光采样分布并重新积累画面，参数同步耗时不等于完整视口响应时间。`NightSkyReference` 用网页 800×450 相机输出对照图，并验证提前排除候选与原始球状噪声一致；`NightSkyRenderProbe` 验证实际 CPU／GPU 受光、零天空纹理、唯一背景光和 GPU 参考相机，`NightSkyTest` 覆盖天文计算、真实星表及保存迁移。

夜景数值参数的范围统一由共享“限”按钮管理，参数目录中的建议 min/max 仅用于初始滑轨尺度。月亮强度等没有隐藏的 0～100 截断；超出建议值的输入在刷新、保存和重载后保持。布尔与枚举保留合法取值，渲染计算中的正值／防除零保护不回写用户数据。`ParameterControlsTest` 用真实 Qt 输入验证超范围数值、自定义范围、关闭范围、点击选中后的滚轮编辑及单一外层滚动条。

天文计算依据 [USNO 恒星时说明](https://aa.usno.navy.mil/faq/GAST)及 [Schlyter 月球摄动与视差算法](https://www.stjarnhimlen.se/comp/tutorial.html)，并以其公开的 1990-04-19 地表观测示例校验。真实星表模式的数据来源、修改与 CC BY-SA 4.0 许可见 [third_party/hyg/LICENSE.txt](third_party/hyg/LICENSE.txt)。

当前外观根据用户提供的 [wcGSDy](https://www.shadertoy.com/view/wcGSDy) 完整源码适配，保留原 seed、球状噪声、层合成及吸收系数。网页末尾 `1-exp(-c*7*1.5)` 的显示结果先转回线性，以保持截图中的色彩和对比度，之后再交由场景统一曝光；远近星光与银河分离时保留默认强度下的合成结果。星点采用网页 800px／CameraZoom=0.35 的固定角尺度，不会随窗口大小变化。相机、地平线消光、曝光和抗锯齿设置不同仍会影响最终画面。

在场景树选中 **Environment Options → Environment → Matte Fog**，可启用共享大气：模型、天空与 HDRI 按同一片空间雾层计算透射和雾光。能见度以米计，表示基准高度处物体对比度降至 2% 的距离，越小则雾越浓。“雾基准高度”默认 0 m；此高度以下密度恒定，以上每升高一个“雾密度衰减高度”（默认 1000 m），密度降至约 37%。地平线自然比高空更浓，相机升高、俯视或巨大模型跨越雾层时使用相同积分，没有独立的背景混合强度。

公里级场景可从能见度 5000 m、基准高度 0 m、衰减高度 1000 m、起雾距离 0 m 开始。降低衰减高度可保留更多高空蓝天；增大则使高处物体和天空一起变朦胧。能见度颜色倍率分别改变 RGB 衰减距离，雾亮度及雾颜色控制散射颜色；“雾亮度相对环境”开启时随环境平均亮度变化。起雾距离会同时跳过模型与天空光线的近段，0 m 最接近连续大气。旧“背景等效距离／背景薄雾高度”在读取时迁移为新的空间雾层，原有能见度、雾色和亮度保留。DAZ 六项 Matte Fog 通道支持导入，但本项目有意扩展为影响背景的高度雾；DAZ Ground Fog 通道尚未实现。

密度积分使用解析式，几何光线积分到表面，天空光线积分到无穷远；无逐步体积采样或额外光线，透明裁切保留正确覆盖率。视口、PNG 和线性 EXR 共用效果。这是平面分层、各向同性散射的空气透视近似：不产生体积光束或阴影，不衰减场景照明，不模拟反射／折射之后的二次雾程或行星曲率。相对亮度使用环境平均辐亮度（Sun-Sky 为天空采样分布），未标定为 Iray 绝对测光；HDRI 已包含的雾不会自动去除。能见度约定参考 [NVIDIA Iray 手册 §3.12](https://doc.realityserver.com/doc/resources/general/iray/manual/manual.241003.LTR.pdf)，高度分层近似也用于 [实时指数高度雾](https://dev.epicgames.com/documentation/en-us/unreal-engine/exponential-height-fog-in-unreal-engine)。`MatteFogRenderProbe` 检查近远对比度、透明贴片、相机升高、天空衔接及 100000 倍远离原点的模型；数值积分对照、导入迁移、保存与 Qt 交互由相关测试覆盖。

环境、色调及水色参数使用与材质相同的颜色调色板，保留线性 RGB 和 HDR 强度；一次确认提交完整颜色，取消不改值。数值框保持原生 Qt 箭头，点击参数行后滚轮调值，未选中时滚动外层页面；颜色弹窗的数值输入同样需要先点击才接受滚轮。修改支持撤销、重做及保存重开。

项目使用独立的 Cycles 运行时来做场景预览，不需要额外启动 Blender、DAZ Studio 或 Iray。

渲染时按需上传可见对象及其使用的材质，释放隐藏头发等资源占用，并缩短静止采样的显示更新批次。`test9.duf` 头部特写的原因分析、实测数据与后续优化方向见 [渲染性能调查](Docs/render_performance_analysis_cn.md)。

在视口里可以查看当前场景，也可以旋转、平移、缩放相机，聚焦到某个对象。现在也支持鼠标操作和 WASDQE 这类键盘移动方式，方便在场景里观察。

除此之外，还可以调整一些环境、色调和渲染相关的选项，让预览效果更接近自己想要的样子。

“项目 → 项目设置”按功能分为“资源与保存”和“渲染”选项卡，内容库路径、保存文件及各组渲染设置均可折叠。“渲染”页包含独立的 50%～100% 渲染倍率、双线性／双三次升采样与 50%～200% 界面缩放，以及 512／1024／2048／4096／无限制纹理最大分辨率、皮肤 SSS、凹凸与法线和透明层数上限。“应用”立即更新当前窗口，“保存”同时保存设置供下次启动恢复。默认保持原画质；纹理或材质质量改变时释放旧 GPU 会话并重新加载资源，保留当前编辑和相机。详见 [项目与渲染设置](Docs/project_render_settings_cn.md)。黄色选择区域始终覆盖在服装等遮挡物上方，重叠表面只叠加一次黄色。材质支持发光色与亮度贴图、色温、亮度单位和单双面发光。

我按自己的习惯顺便还做了个单手（纯鼠标）自由移动相机的交互模式，但需要用一个支持侧键的鼠标。

### 调整角色和姿势

场景编辑支持 `Ctrl+Z` 撤销、`Ctrl+Y`／`Ctrl+Shift+Z` 重做，包括新建和替换场景；连续拖动计为一次操作，相机导航不进入历史。“项目设置 → 资源与保存”可调整历史上限，默认 50 条。编辑后自动写入恢复点，异常退出后再次启动会询问是否恢复最后场景与暂存参数。覆盖范围与扩展接入方式见 [撤销、重做与异常恢复](Docs/undo_redo_cn.md)。

目前已经接入了 Genesis 8、Genesis 8.1 等角色的基础骨骼和蒙皮处理，也可以加载和应用 Pose DUF 姿势文件，也对一些 GeoGraft 做了支持。

在场景树或者骨骼层级里选择角色部位之后，可以对它进行位置、旋转和缩放调整。项目现在也在逐步完善 FK 和 IK，让摆姿势的时候不需要完全依赖传统的骨骼层级操作。

现在也可以使用视口 Gizmo 直接平移、旋转和缩放节点，平移支持三轴及三个平面，平移与旋转分别记忆 Local／World；未命中手柄时仍可拖动 IK。Local／World 右侧的功能模块提供地面对齐比例与 `Ctrl+D` 对齐到地面，适用于角色、普通物体及 DAZ Instance。菜单、3D 工具和角色功能默认同行，可独立移动、换行或浮动，并保存布局。具体操作见 [Gizmo 与顶部栏说明](Docs/gizmo_controls_cn.md)。

### 调整 Morph 和角色参数

“对齐到地面”旁的砝码可以为角色添加独立的生长与体重参数，或为普通物体添加密度与重量参数。年龄支持小数和步进，后台测量标准站姿身高、体重及部位重量；生长组与 Morph 列表均可折叠。使用 `Ctrl+S` 将场景修改保存到同名 `.dufex`，同时冻结完整 DUF 底稿并生成视口缩略图。下次打开 DUFEX 恢复修改后的场景，原 DUF 独立打开；内容库与近期记录同时显示同名文件。v2 暂不包含物理模拟和城市 PCG，外部 DSF／贴图仍需内容库。详见 [生长与保存说明](Docs/growth_weight_dufex_cn.md)。

若 DUF 含可匹配的原生生长或密度通道，对应扩展组会自动挂载并按项继承原值；未匹配项保留默认值。“步长”控件的滚轮与上下按钮增量为 0.25。本轮兼容性修复及验证见 [体验反馈记录](Docs/experience_feedback_execution_cn.md)。

“编辑 → 测量单位…”设置全局倍率，身高按倍率、重量按倍率立方显示，并自动选取 cm／m／km 或 g／kg／t。年龄滚轮与上下箭头遵循“步长”。未指定文件时默认打开空场景，详见 [面板与测量单位](Docs/growth_weight_ui_cn.md)。

项目可以读取角色和资产中的 Morph 参数，并在参数面板里进行搜索、分类和调整。

参数既可以通过滑块调，也可以直接输入数值。部分 Formula、ERC 和 JCM 关系也已经接入，所以一些参数在改变姿势或形态之后，可以跟着一起更新。

### 服装和附加物跟随
