# 场景删除、资源生命周期与复合 DUF 修复

本轮属于 007 之后的功能修复，008 未启动。

> 后续视觉复测更正：本报告的 `scene3-complete-ui` 仅证明加载、渲染和资源流程跑通。用户随后指出脸型与服装明显错误；它不代表形变正确或视觉验收通过。原生求值修复及 DBZ 数值对照见 [形变修复报告](scene_deformation_execution_cn.md)。

## 使用方式

- 在场景树或视口选中整个模型，按 Delete，或使用“编辑 → 删除选中对象及其子对象”。场景树右键也提供此入口。
- 删除人物会删除其子对象、经骨骼挂接的附件及 Fit To 穿戴物；单独删除衣物不会删除人物。选中骨骼部位时删除入口禁用，先选择所属模型。
- 灯光同样可以删除。“文件 → 新建空场景”释放当前文档；“打开场景（替换）”继续用于替换，“添加 / 应用 DUF”继续用于合并或应用预设。

## 实现与资源所有权

删除按场景节点父链及 Fit To 依赖计算对象集合，统一重映射实例、网格、材质、贴图、Morph、骨架、公式图与编辑快照。保留未删除对象的当前姿势和变换，保留仍被使用的共享资源。

材质替换完成后回收旧材质与无引用贴图，并按文件及色彩空间复用贴图；没有匹配表面组的预设不改变文档。原始公式和完整加载诊断写盘后不再随编辑文档复制；合并不再积累嵌套历史报告。参数发现的路径缓存也在成功、异常退出时释放。

渲染线程先停止 Cycles 会话，释放覆盖绘制和显示资源，再销毁适配器、旧求值器、网格和射线缓存。文档替换仍通过世代号隔离旧的编辑和选择消息。某份文档渲染失败时，线程保留处理新文档的能力。

## `3.duf` 的失败原因

实际文件位于 `H:\G1\Scenes\3.duf`，不是 `H:\G1\scene\3.duf`。原版完成几何和 Morph 发现后，在眼镜 `glasses_06dazuv_8440` 上报“当前只支持 General 权重蒙皮”。文件包含 37 个几何对象和 153 张贴图。

眼镜采用 Local 绑定，但 X / Y / Z 和 scale 四份权重图相同，每个顶点只有一个权重为 1 的关节，因此可等价按刚性 Linear 变换处理。手机 `Smart Phone_7617` 为 General 绑定，额外 scale 图与 node 图相同，也无需因额外图而拒绝加载。代码验证权重记录、各图相等及刚性条件，不把一般 TriAx 或不同的缩放图冒充为已支持。

首次显示验证还发现：三个 G8.1 人物及一双鞋使用内嵌派生几何，`source` 指向外部 DSF。原实现仅扫描内嵌几何所在 DUF，导致人物没有 Morph 目录和骨架。现保留内嵌网格，并逐级验证 `source` 的顶点数量与面顶点连接关系，沿兼容的源资产发现 Morph、G8.1 / G8 参数覆盖和 SkinBinding。拓扑不符时给出诊断，不套用不兼容的索引；循环引用明确拒绝。新增双人物合成测试验证保存的 Morph 和姿势确实改变顶点，且互不污染。

继承恢复后，真实场景发现 31 套蒙皮，每个人物各 6,808 项参数。另修复跨资产骨骼匹配：此 G8.1 资产存在 `id=lCarpal2-1, name=lCarpal2` 和 `id=lCarpal2, name=lCarpal4`，不能把 name 与 ID 的候选混在一起报歧义或错误绑定。现优先采用唯一 name，同名时以 ID 消除歧义，缺少名称匹配时才按 ID 回退，真正的歧义仍拒绝。`scene3-bindings.json` 验证了全部 25 条 Fit To 关系。

## DUF 内容分派

DUF 的容器定位与 [DAZ 官方文件格式说明](https://docs.daz3d.com/public/dson_spec/format_description/file_types/start) 一致。入口结合实际节点、几何、材质及动画通道判断用途，不再只依赖互斥的 `preset_*` 白名单。

带几何实例的文件走完整场景加载；同时包含选中对象的单帧姿势 / 形态通道及材质的预设，将二者准备成功后一起提交。只有资产库而没有场景实例的文件仍明确说明需要实例引用。场景内的多帧动画时间线尚未求值，此次增加明确诊断；现有节点与 Modifier 保存值仍由加载流程处理。

## 验证

- 10 项工程 CTest 通过。新增检查包括人物 / 衣物 / 骨骼附件删除、索引重映射、其他人物姿势保留、64 轮增删、64 次材质替换、最后对象删除后的空场景求值，以及刚性 Local 和冗余 scale 图的正反例。
- 副屏 `--lifecycle-test` 使用两份带 1024 × 1024 贴图的 DUF，完成 8 轮追加、删除、清空、替换，50 个稳定状态采样全部通过。旧文档的弱引用均失效；每轮清空后模型、网格、材质和贴图计数均为 0。另注入公式图错误，验证随后新建空场景仍可渲染。
- 进一步延长到 32 轮、194 个稳定状态（`artifacts/scene-lifecycle/long-ui`），旧文档引用释放和空场景资源归零检查均通过。空场景私有提交内存在约 1974–1992 MiB 内波动，首末轮相差约 7 MiB；没有与每次加载资源大小相当的累积增长。内存包含驱动和分配器缓存，不能据此宣称任意资产或任意时长均无泄漏。
- 最终构建与 10 项回归日志位于 `artifacts/scene-lifecycle-delivery-build.log`。可用 `python tools/check_scene_lifecycle.py --cycles 32 --output artifacts/scene-lifecycle/long-ui` 生成两份贴图样例并在副屏重放全部流程。早期内嵌顶点测试曾因直接比较浮点数而失败，已改为有容差的数值断言；源资产及姿势隔离检查均通过。

真实场景最终验证见 `artifacts/scene-lifecycle/scene3-complete-ui`：副屏显示 PASS，37 个资产对象、31 套蒙皮、三个人物各 6,808 项参数。渲染使用 38 个网格，其中一个为预览地面；25 条跟随关系绑定 1,368,903 个顶点，并匹配 209 个穿戴物原生 Morph。Morph、Formula 和保存姿势已进入实际变形，最大顶点位移约 0.917 米；显示世代一致，GPU 互操作回读为 0。截图为同目录 `scene.png`。

`scene3-final.json`、`scene3-ui` 为遗漏源资产继承的中间结果；`scene3-derived-ui` 保留了随后发现的骨骼 ID / name 歧义失败记录，均不作为最终完成证据。最终汇总与部署二进制 SHA-256 位于 `artifacts/scene-lifecycle/summary.json`，已验证 `out/DazFastViewer.exe` 与本轮构建产物一致。

本场景最终首次显示约需 5 分钟，主要仍受完整资源与参数发现影响。当前结果证明该场景能加载、求值和显示，不代表完整 DAZ Studio Golden、一般 TriAx、HD / SubD、Iray 等价材质或多帧动画已经完成。
