# `3.duf` 场景加载性能分析

本轮回应 007 之后的加载效率问题，不启动 008。交付包括当前实现的耗时证据、代码原因、优化次序及可复用的诊断入口。

后续已完成一轮修复并部署编辑器；本文保留优化前的诊断基线，当前结果见[加载优化执行报告](scene_load_optimization_execution_cn.md)。

## 测量范围

- 实际测试文件：`H:\G1\Scenes\3.duf`，3,597,371 字节。用户给出的 `H:\g1\scene\3.duf` 不存在，采用规范和历史验证中同名的真实文件。
- 使用项目配置中的四个内容库及原有优先级；资产只读。
- CPU：AMD Ryzen 7 5800X，8 核 / 16 线程；物理内存约 64 GiB。H 盘通过 Realtek RTL9210B-CG USB 桥接连接。
- Release / MSVC 优化构建。未清空操作系统文件缓存，因此不称为严格冷启动；本次数据也不是 DAZ Studio / Blender 的受控对比跑分。
- 无窗口诊断调用与编辑器相同的场景加载、Morph 发现、骨架、公式编译、报告写入及首次形变代码，另外记录选取索引构建。它不包含 Qt 界面、Cycles 材质/贴图上传、GPU BVH 和实际首帧。
- 计时范围有嵌套；父项已经包含子项，不能把所有行直接相加。文件读入时间包含 C++ 字节读取和缓冲区构造，不等于纯磁盘等待。

## 为什么加载远比读取一个 DUF 昂贵

当前入口按顺序执行以下工作：

1. 解析 DUF 及其 DSF / UV 依赖，建立场景节点、网格、材质、纹理路径和派生几何源关系。
2. 为对象递归发现 Morph 目录；处理多内容库的优先级、G8.1 对 G8 的覆盖、别名、缺失依赖与引用修复；完整解压、解析所有候选参数文件，并把所有稀疏顶点差值装入内存。
3. 再读取资产的骨架和 SkinBinding，转换权重，应用当前角色保存的姿势。
4. 将符号公式绑定为运行时通道，处理别名、循环和不支持的依赖，为每个角色编译自己的公式图。
5. 写入完整诊断报告，释放部分加载期数据，并准备属性快照。
6. 渲染线程复制场景、建立部位选取区域和形变运行时；运行时重新验证全部 Morph 差值，再建立 Fit To 表面对应关系。
7. 求值 ERC / JCM，应用有效 Morph、蒙皮、服装跟随、平滑和碰撞，然后构建渲染与视口选取数据，最终由 Cycles 生成首帧。

这里同时进行了“显示保存的场景”和“准备全部参数供以后编辑”两类工作。当前求值器已经只遍历有效 Morph 的差值；主要问题在它之前的发现、解析、校验和数据准备，不能把已存在的 Active Set 当作尚未实现的优化。

## 代码中已确认的问题

### 全量差值与元数据没有分离

`runtime::Morph` 将名称、范围、公式相关元信息、实例初始值与 `std::vector<SparseOffset>` 放在同一个结构里。`discover_morphs()` 不论参数当前是否影响场景，都完整读取并校验 `deltas.values`。一个含大量大网格 Morph 的头发资产，少量文件也会比几千个小控制器文件更昂贵。

不能仅依据 DUF 中保存值为零就忽略参数：ERC / JCM、负值抵消和服装跟随可能让其最终值非零。正确的延迟加载边界是先解析必要的标量依赖、求出最终权重，再取得这些参数的顶点差值；参数目录可独立供 UI 搜索。

### JSON 按值读取造成大数组复制

本仓库的 `nlohmann::json::value()` 返回值对象。`doc.value("modifier_library", J::array())` 与 `modifier.value("morph", J::object())` 会复制相应 JSON 子树；即使左侧写 `const auto &`，也只是延长副本的生命期。

因此，一份差值数组可能经历 DOM 构造、库数组复制、Morph 子树复制、转换为连续偏移数组，以及中间副本销毁。首先应对大型子树使用生命周期安全的 `find()` / `at()` 常量引用；长期可用专门的解析器直接写入数值缓冲区，避免为每个数字建立 JSON 节点。

### 逐条树节点校验及重复校验

`daz/morphs.cpp` 用 `std::set<uint32_t>` 校验每份差值的顶点索引；`runtime/morph.cpp` 的构造函数又对所有差值使用相同方式校验。每条记录都涉及树查找，并可能创建一个独立堆节点。

可用可复用的连续标记数组或带世代号的索引标记，将去重从 O(N log N) 改为 O(N)，减少逐条分配；索引范围与有限数检查仍保留。进一步让校验过的不可变资产携带有效性保证，运行时只检查绑定拓扑和版本，不再为每个实例重复验证同一份差值。

### 解析缓存有阶段边界，实例缓存仍然深复制

几何阶段的 `Repository::documents` 只存在于 `daz::load()` 内。参数发现和骨架阶段又调用 `read_document_file()`。场景 DUF 也会作为内嵌 Modifier 候选被各对象读取。

近期的平滑/碰撞导入还增加了一个具体重复入口：`loader.cpp` 在 `scene.modifiers` 中筛选没有直接 `channel` / `skin` 字段的条目，然后先解析其外部资产，再检查是否为 smoothing。本场景 11,533 条场景 Modifier 中有 8,419 条进入该候选范围，使几何阶段实际解析了 **4,229 份文档**，其中读取/解压/JSON 解析就占 **27.59 秒**。这些参数中的许多又会进入后续 Morph 发现。应通过共享的类型化 Modifier 索引或统一解析流程识别平滑设置，避免仅为识别类型就提前读入全部 Morph 差值；不能简单忽略可能从基础资产继承的平滑设置。

Morph 发现已有 `cached_targets`，路径解析也已有缓存；同资产的多个角色并非完全重新扫描。但缓存命中仍复制整个 `target.morphs`、公式源和报告。首次写入缓存本身也保存一份完整副本，包括只出现一次的资产。

推荐把不可变资产定义、差值缓冲区、公式模板与实例权重/姿势/可见性拆开。多个角色共享资产数据，各自保留输入值、求值状态和变形输出。不要简单地永久缓存全部 JSON DOM，否则会用更高内存峰值换取解析速度。

## 建议实施次序与验收

| 次序 | 改动 | 目的与限制 |
|---|---|---|
| 1 | 大 JSON 子树改引用；差值预分配；批量读文件；连续索引标记 | 优先减少复制、分配与重复校验，保持现有加载结果与参数完整度 |
| 2 | 统一 Modifier 类型识别；加载会话内共享类型化资产；不可变差值与实例状态拆分 | 减少几何/参数/骨架阶段的重复解析和多角色副本；保持实例参数相互隔离 |
| 3 | 参数元数据索引与差值按需加载；带版本的磁盘缓存 | 缩短首次可见时间及再次打开时间；初次建立索引与缓存命中须分别测量 |
| 4 | 在有界内存预算下并行解压/解析独立资产 | 利用多个 CPU 核；合并仍遵守根目录优先级和 G8.1 空覆盖语义 |
| 5 | 按剩余占比优化 Fit To 索引复用及 Cycles 准备 | 以测量决定，不先假设 GPU 或碰撞是主瓶颈 |

缓存键至少考虑内容库及顺序、规范化资产身份、文件变化、解析器/缓存格式版本、几何拓扑与绑定条件。公式模板应与每个实例的当前输入及求值缓存分开。内容库变更和空覆盖必须使相关条目失效。

验收应同时检查：真实场景首帧与各阶段耗时、峰值内存、相同的对象/参数/公式及诊断结果、所有对象的首次形变顶点、两个人物参数隔离、负值抵消、G8.1 覆盖、HD/缺失依赖处理、服装/发丝跟随和可见性。不能通过删除参数、关闭碰撞、遗漏隐藏但仍被依赖的对象或改用未变形网格来取得加载加速。

在完成优化后的同条件测量前，不把设计目标写成已实现的倍数或秒数。

本轮诊断构建成功，10 项既有工程 CTest 全部通过；日志为 [load-profile-ctest.log](../artifacts/load-profile-ctest.log)。已部署的 `out/DazFastViewer.exe` 保持原版本。没有把这份性能报告当成视觉 Golden 或后续阶段验收。

## 补充：未在 DUF 中使用的 Morph 如何交互加载（2026-09-22）

本节记录实施前的交互方案与代码可行性分析；后续实现、测量和边界见[加载优化执行报告](scene_load_optimization_execution_cn.md)。按需加载必须保留用户在运行中使用新 Morph 的能力：参数发现范围仍是当前内容库中与目标兼容的完整目录，不能缩减为保存 DUF 的引用集合。

### 推荐默认行为：自动异步补载与局部更新

1. 参数目录保存名称、分组、范围、资产身份、拓扑约束、差值数量/来源及公式依赖。支持状态与差值驻留状态独立，未载入数据的已支持参数仍可搜索、选择和输入。
2. 用户首次修改该参数时，立即记录期望值并显示“加载中”；后台请求合并重复资源，读取并校验所需差值。连续拖动只保留最新期望值，不重复创建读取任务。
3. 请求集合由公式求值和跟随依赖决定。一个控制器可能驱动多个 Morph、骨骼或穿戴物；不能只补载用户点击的那个文件。元数据缺失时先完成所需索引/依赖发现，再确定差值集合。
4. 工作线程交付不可变缓冲区，由持有运行时的线程接收；检查文档世代、资产身份和版本，丢弃已删除对象或已切换场景的过期应用请求。
5. 所需数据齐备后应用最新属性值，更新受影响的角色、衣物、附件及碰撞依赖，并输出网格 `Delta`。等待期间保留已成功显示的结果，界面明确区分期望输入与已生效结果，避免把人物变了而服装未更新的半成品作为完成状态。
6. 差值保留在有界缓存内；缓存仍驻留时，再次拖动无需读盘。跨实例可共享不可变差值，实例权重和形变输出继续隔离。缓存淘汰遵守当前求值/任务的引用生命周期。

例如 DUF 没有使用某个体型参数，用户仍可搜索它并拖到 `0.7`；首用时自动补载，完成后按当前最新值更新人物和服装。选中一个具体参数后可做低优先级预取，但不应因选中角色就预读其全部 Morph，否则会重新引入全量载入开销。

### 手动按钮的用途

| 操作 | 推荐行为 |
|---|---|
| 正常修改已发现、受支持的参数 | 自动异步补载，无需每次额外点击刷新 |
| “刷新参数目录” | 检查运行期间新增/替换的 Morph 文件；增量更新所选角色的目录及必要的公式绑定，按稳定资产身份保留兼容的现有输入 |
| “重试加载” | 对读取失败的资源重试；成功之前不把对应编辑标为已生效 |
| 可选“手动应用”模式 | 暂存一组参数修改，点击“应用”后合并补载和求值，适合大资产或批量操作；作为独立模式提供明确的未应用状态 |

“刷新参数目录”与“补载已知参数的数据”应分开。前者可能需要对该角色及其依赖重新编译部分公式图，后者通常只补齐缓冲区。新增参数的发现仍遵守多库优先级、G8.1 空覆盖、几何兼容和原有不支持项的处理。

### 当前实现需要补齐的接口

- `editor/parameters.cpp` 根据 `unsupported` 禁用输入；`daz/formulas.cpp` 及参数说明会根据 `offsets.empty()` 判断能力。必须增加明确的差值存在性/载入状态，不能让延迟载入伪装成“没有差值”或“公式控制器”。
- `runtime/morph.cpp` 的 `set_morph()` 在值未改变时直接返回，且仅在差值非空时标记网格变化。数据安装完成必须显式触发重新求值，不能指望再次提交相同权重自动生效。
- `editor/renderer.cpp` 在文档指针变化时销毁旧运行时并重建 Cycles Session；当前增量编辑则经 `runtime->evaluate()` 和 `adapter->apply(delta)` 更新。应增加专用的资源就绪消息/缓存安装接口，复用增量路径，避免通过替换整个 `Document` 实现补载。
- Morph 顶点数和拓扑不变时，可以保留材质、贴图和场景实例；受影响几何仍可能需要 GPU 上传、BVH 更新和重新采样。现有 `Delta` 以网格位置数组为单位，并不是只上传几个变化顶点；更细粒度上传是后续优化，不作为本方案已具备的能力。
- 首次建立完整元数据索引仍有成本，特别是 gzip DSF 不能任意跳读压缩流。需结合持久索引、跳过大数值数组的元数据解析与后台索引更新；仅把差值 vector 留空、却照常构建完整 JSON DOM，无法消除此前的解析瓶颈。

专项验收应包含：DUF 未使用的 Morph 首次修改、纯控制器驱动多个差值、角色与服装同步、加载期间连续拖动/归零/撤销/切换场景、两角色共享资源而输入隔离、失败与重试、运行期间安装新 Morph 后刷新，以及目录更新前后参数值保留。
