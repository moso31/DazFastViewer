# 下一轮需求：视口操作与角色移动的性能优化

当前项目正在研发中，具体进度可以看 `D:\Github\DazFastViewer\Docs\daz_cycles_runtime_spec_final_cn.md`。007 已经基本完成，008 还没有开始。内容浏览器的搜索、图标预览、近期使用和紧凑布局已经完成，这次主要处理测试中剩余的性能问题。

首先是视口。每次拖动视口以后，都需要等待很长时间才能继续看到正常的画面。这里请分别检查调整视口大小、拖动停靠面板，以及旋转、平移、缩放相机这几种情况，不要都归结成光照重新计算。前一轮已经分析过最近使用的 `H:/G1/Scenes/6.duf`，发现两次视口尺寸变化伴随约 45.8 秒和 52.1 秒的场景同步，其中一次宽度只变化了 6 像素。请优先解决这种小幅调整也会重新建立整个渲染会话的问题，尽量复用已经加载的场景和资源。

另外，移动角色的时候，画面也会很卡。我理解这可能涉及动态场景，需要重新计算光照，但不希望每次只是移动一个角色，就让整个场景做大量重复计算。请检查角色平移、旋转时的处理流程，尽量只更新发生变化的对象，以及确实需要跟随的服装、头发和附件。没有变化的其他对象、几何、材质和贴图应该尽量复用。

交互效果可以参考现有相机移动时的低清预览：操作期间先保证能及时看到最新位置，停止操作后再恢复完整画质。连续操作时不要积压旧的位置，让画面一直追着旧操作慢慢更新。注意不要为了提速破坏服装跟随、附件挂接、碰撞、对象选取和高亮等现有功能；继续保持不开降噪的要求，最终画质也不要降低。

前一轮的分析在 `Docs/interaction_latency_analysis_cn.md`。其中提到了视口尺寸变化会重建 Cycles 会话、角色移动没有接入交互预览，以及移动对象后会重建全场景选取和高亮数据等问题。注意这些目前只是完成了分析，还没有实施性能优化，也没有证明它们各自占用了多少时间。

这次请先确认实际瓶颈，再按优先级实施优化。验证时仍然只使用副屏，优先用 `6.duf` 做可复现的短操作，对比操作到第一张新画面、停止操作到完整分辨率恢复的耗时，并和画面噪点逐渐收敛的时间区分开。不要只用编译成功或功能测试通过说明性能已经改善，也不要把这次优化算作启动 008。
