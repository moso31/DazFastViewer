# 换装增量更新与细分简化执行记录

日期：2026-09-24。承接[优化前分析](scene_rebuild_latency_analysis_cn.md)，按用户授权实施性能优化，并将细分界面简化为一个关键参数。程序部署到 `out/DazFastViewer.exe`，原始 DAZ 资源保持只读。

## 使用变化

选择模型，在参数面板搜索“渲染细分等级”，或进入 `General / Mesh Resolution`。界面只保留这一项，移除独立的视口等级、分辨率开关、算法、边界插值和法线平滑控件。

- 此等级同时用于当前预览与最终渲染，修改会实际更新渲染拓扑。0 表示基础网格。
- 初始值使用导入的视口等级与渲染最低等级的较大值，保持原有最终渲染精度；导入时关闭细分的模型初始为 0。
- 算法、折痕和边界设置仍按资产导入，避免改变原资产的表面特征，只移除对应的编辑入口。
- 相同值不重复提交；快速输入合并到最新快照。追加、删除、挂接和材质修改保留已有模型的级别。
- 支持范围为 0～6，实际可用上限还受单网格 **400 万细分面**预算约束。过高等级拒绝提交，控件恢复原值并显示原因；不会偷偷降低精度。DAZ 人物可能在到达数字上限前就触发预算。
- 导入时已经带有无效／过高等级的场景显示错误后，可以降低相应模型的等级，重新准备渲染。

这些设置仅影响当前编辑会话，不回写原 DUF。普通 OpenSubdiv 细分不会生成 DAZ HD Morph 的额外雕刻细节。

## 实现与原因

旧路径将换装、删除和所有细分参数变更都视为新文档加载，反复销毁 Cycles 会话，重新计算已有衣物碰撞并加载整个设备场景。此前 `test7` 每步约 4.6～6.1 秒碰撞计算、约 4 秒完整场景同步，显示资源销毁后另有约 4 秒空画面。

现在细分等级保存在轻量编辑快照中，不复制整个 Document，也不重新建立形变运行时。基础 Morph、骨骼、Fit To 和碰撞保持原结果；只重建受影响网格的细分模板和渲染拓扑。写入设备网格前检查顶点数量，构建模板前检查面、UV、折痕、等级与细分面预算，并启用 OpenSubdiv 完整拓扑验证。

换装和删除继续准备新文档，但复用原 Cycles Session、显示驱动和未变化的几何、Shader、贴图资源。按稳定身份同步对象增删与拓扑变化；材质数组／贴图索引压缩不再迫使未变化材质重新编译。增量同步同时覆盖曲线头发、GeoGraft 遮盖面、实例、灯光与环境。不同 UV、细分设置或遮盖面的同源网格使用独立身份，避免交叉更新。

已有附件的表面绑定按基础拓扑、位置及相对变换复用。碰撞缓存包含未修正输入、宿主形状、相对变换、参数，以及相关 GeoGraft 的形状和可见性；形状或依赖变化时重新计算。新衣物仍需要实际绑定和碰撞，不会跳过这些步骤。

更新期间保留最后有效帧，状态栏显示“正在更新场景…”。显示队列积压时可回收尚未显示的完成帧，保留正在显示的纹理。退役 Shader 清空贴图引用后放入可复用池，避免 Cycles 不支持删除 Shader 导致反复换装不断创建节点。

前后完整视口均为 731×836。新版细分操作先提供 182×209 的交互预览，再恢复完整分辨率；表中分别列出两个时间，避免将低清首帧当成同分辨率对照。分辨率核对见 `full-resolution-analysis.json`。

原测试的“只改最终渲染字段”两项已被移除的双等级设计替代；新版另测 2 → 0 → 2，不把不同操作强行作为前后对照。最终原始记录为 `artifacts/rebuild-optimization/test7-delivery/`。六次操作全程复用一个会话，操作期间提交空画面的测量值均为 0；旧画面等待期间仍会短暂停留。

新版 2 → 0 和 0 → 2 首张新图分别约 0.18、0.40 秒，完整分辨率为 0.24、0.46 秒。最终一轮的采样峰值为工作集 5.59 GiB、私有提交 11.04 GiB、整张显卡显存 7,004 MiB，和优化前同一量级。本次收益主要来自省去重复计算及资源重建，不是大幅降低常驻内存。采样约每 0.5 秒一次，显存包含其他程序，也不等于瞬时分配峰值。

## 边界

没有获得之前崩溃时的转储，无法确认每次历史崩溃的具体触发点。本轮针对可确认的全量重建、拓扑写入及高等级分配风险作了修正，并完成上述反复切换验证；不能承诺任意损坏资产或极端场景都不会耗尽内存。
