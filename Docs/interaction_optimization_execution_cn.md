# 视口与角色移动性能优化

本轮属于 007 后的交互性能修复，008 未开始。按用户中途更正，正式验证场景改为 `H:/G1/Scenes/test3.duf`，界面测试均在副屏 `DISPLAY2 / VG279QL1A`。此前 `6.duf` 的分析记录保留为历史背景，不混入下表。

## 测量口径

保留修改前的程序 `out/DazFastViewer.interaction-baseline.exe`，仅加入计时与短操作入口；优化程序运行同一场景、同一项目配置及同样的前八项操作。每组相机或角色连续操作持续约 480 毫秒，发送八次输入；尺寸操作单独记录。初次加载和着色器准备不计入交互延迟。

“第一张新图”指输入后新渲染版本首次完成 `SwapBuffers` 提交；“恢复完整分辨率”指停止操作后，最新相机／编辑版本首次以完整视口尺寸呈现。每次均核对版本和尺寸，不能用旧图继续显示或仅完成 CPU 求值代替。这里没有测量显示器物理扫描输出；也不将第一张完整分辨率画面等同于噪点收敛。

原始证据在 `artifacts/interaction-performance/`：`events.csv`、`interaction-progress.json`、`editor-check.json`、`editor-render.json` 及副屏截图。使用 `tools/analyze_interaction.py` 从实际呈现事件重新计算延迟，并关联最后一次输入的版本；各 CPU 阶段可能嵌套或与渲染并行，耗时不能直接相加。

相机原本已有预览，仍保持相近延迟量级；少量重复中的几十毫秒差异不能当作统计显著的相机提速。尺寸变化从每次新增一个会话变为不新增会话，角色移动的秒级 CPU 等待则在两轮中稳定消除。程序和场景 SHA-256 见 `comparison-manifest.json`。

## 已确认的瓶颈

`test3-baseline` 中，6 像素缩小和停靠分隔变化都新增一个 Cycles 会话，场景同步分别约 6.57、6.68 秒，旧会话清理约 0.58–0.66 秒。相机旋转、平移、缩放本来就在复用会话，首次新图约 76–105 毫秒，不能把这些操作统一解释为重新加载或计算光照。

角色移动的主要 CPU 瓶颈是碰撞：单次 `collision_evaluate` 最高约 10.4 秒。角色与穿戴物一起移动时，原来的世界矩阵逆乘比较及 GeoGraft 实例变化标记触发了不必要的碰撞表面索引和修正。原版高亮重建约 234–251 毫秒，选取重建约 109–114 毫秒，诊断扫描约 27–30 毫秒；公式输入约 1 毫秒，没有发现整体重复蒙皮是这次移动的主因。

## 实现

- 视口尺寸变化保留 Cycles 会话、场景、材质及贴图，仅更新相机和渲染缓冲。停靠位置变化但尺寸不变时不重置渲染。OpenGL 输出缓冲按容量扩展，不随几像素缩小或预览切换反复分配；扩容遵守帧槽 fence 和 CUDA 注册释放顺序，旧画面在新图就绪前继续显示。
- 角色编辑采用现有相机预览质量：宽、高各 1/4，最多 2 样本。拖动保持期间维持预览，释放或停止输入后恢复完整分辨率。快照只保留最新输入；每轮消费当前快照，不建立位置队列。预览帧之间允许完成呈现，避免连续重置导致始终没有新图。
- 根据实际 Delta 判断编辑是否需要重新渲染；曝光等只影响显示的色调修改保留已有累计采样，不能因为参数行也使用滑块而触发预览重置。
- 纯实例变换／可见性变化跳过未改变的 Morph、Pose、公式和服装投影求值。碰撞相对变换从依赖树中消去共同祖先，精确复用共同移动时的结果，没有采用忽略小位移的容差。独立服装位移、实际网格变形及 GeoGraft 相对位置／可见性变化仍触发必要碰撞。
- 选取数据改为每个网格的局部三角面树加实例矩阵和包围盒；刚性移动更新实例即可。高亮顶点保留在局部空间，绘制时应用实例矩阵；只有实际发生网格变化时才重建受影响对象。诊断包围盒也限定到受影响目标。
- 补充分段计时：场景同步、编辑准备／求值、碰撞、Adapter、会话重置、选取、高亮、诊断，以及渲染缓冲准备、路径追踪和显示上传。`render_work_cpu` 是整个渲染工作的宿主耗时，不直接称为 GPU 光照耗时。

最终采样仍为 Blue Noise First、4096 上限、自适应阈值 0.01，反弹设置不变，降噪关闭。完整分辨率恢复之后仍需继续累计样本；此前无降噪收敛的验收状态不由本轮改变。

## 验证与边界

14 项工程回归全部通过。新增检查覆盖共同平移／旋转／非均匀缩放时的碰撞复用、无关对象隔离、独立服装微小位移、GeoGraft 位移和可见性变化；已有骨骼／表面附件、Morph、Pose 和服装跟随检查继续通过。选取回归核对共享网格、实例变换、非均匀缩放的命中距离、隐藏和实际网格变化；参数控件检查拖动释放、失焦和捕获丢失。

副屏小场景的原有 32 项导航检查通过，包含组合输入、捕获／焦点丢失、侧键和层级联动；异步 Morph 首次加载、连续输入取最新值、手动应用、目录刷新后保持暂存值和重置流程也通过。证据分别为 `navigation/` 与 `lazy-ui/`。这些功能检查用于保护现有行为，性能改善仍以上述真实场景呈现计时为依据。

真实 `test3.duf` 的角色→Head→眼球／嘴唇选取与高亮、穿戴场景角色选取、绑定物场景树选择、附件可见性恢复共 11 条检查通过，见 `test3-picking-complete/`。旧测试在原版程序中也无法处理本场景：它从未变形网格定位、假设角色朝前及全身中心必有几何，且没有处理独立眼镜镜片遮挡。现改用实际求值后的部位位置和朝向，记录镜片正常命中后临时隐藏该挂接附件，完成部位检查后恢复可见性，并寻找真正命中的身体射线。测试没有修改产品的选取规则或 DUF 文件。全程未新增 Morph／蒙皮求值，几何更新为零；已检查头部和嘴唇截图中的覆盖位置。

`test3-final` 的十项短操作和六项交互边界全部通过。视口实际从 758×836 扩为 908×836、随后缩为 588×836；扩容首次出图约 92 毫秒、完整分辨率约 275 毫秒，缩小约 96／263 毫秒。面板浮动和重新停靠没有增加会话，只移动浮动面板没有渲染重置；按住编辑后静止 700 毫秒仍保持预览，释放后恢复完整分辨率。曝光在拖动保持及恢复原值时均没有重置渲染。

角色平移和旋转各输入八次，分别呈现六个不同编辑版本，过时的中间值被合并。最后一次输入到相应新位置呈现约 82／87 毫秒，停止操作后约 19／22 毫秒已看到最终位置，随后恢复完整分辨率。每次实际应用只更新该角色依赖链的十个实例，几何更新、Morph／蒙皮重算和碰撞重算均为零；全部操作后，局部顶点哈希一致，所有实例矩阵逐值恢复初始状态。GPU 回读为零。

该轮缩放时场景同步最高约 1.57 毫秒；角色变换求值最高约 0.10 毫秒，选取更新约 0.003 毫秒，高亮数据更新约 0.001 毫秒，诊断扫描约 5.2 毫秒。上述短操作的输出缓冲准备最高约 1.2 毫秒，扩容时显示更新最高约 4.9 毫秒。保留的主要等待来自预览／完整画面的实际渲染、150 毫秒静止窗口和呈现调度。

以上“完整分辨率”首帧均只有一个样本，截图仍可见噪点。这证明更新延迟改善，不代表噪点已经收敛，也不表示所有复杂场景或独立服装碰撞都能达到同样延迟。首次加载、真正 Morph／Pose 变形、必要碰撞和最终光线追踪仍有其计算成本。

用户更换测试场景前，`6.duf` 的早期优化试跑已消除会话重建，但仍记录到数秒的 `render_work_cpu` 等待。切换到 `test3.duf` 后加入了更细的路径追踪／缓冲／显示计时，未再对 `6.duf` 归因或复测，因此本页的延迟结论仅适用于指定的 `test3.duf` 操作，不能外推为 `6.duf` 的剩余等待也已解决。
