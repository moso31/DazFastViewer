# 007 后场景加载与 Morph 按需交互修复

本轮沿用 007 后的现有场景功能，不启动 008。诊断基线、阶段定义和原始瓶颈见[性能分析](scene_load_performance_analysis_cn.md)。测试场景为 `H:\G1\Scenes\3.duf`，没有修改原始 DUF 或内容库。

## 已实现的行为

- 参数目录仍发现内容库内所有兼容 Morph，包括 DUF 没有引用、初始权重为零的参数。隐藏参数、别名、ERC / JCM、G8.1 空覆盖和 HD 支持边界沿用原规则。
- 差值数据与参数元数据分离。多个角色共享同一份不可变差值，各自保留输入和变形结果；选中角色不会触发全部差值加载。
- 首次操作参数时先求出公式和服装跟随后的实际权重，再异步补齐所有非零依赖。重复请求合并，提交最新输入；等待或失败时保留上一份完整渲染结果。归零或切换文档后，迟到任务只完成资源缓存，不会回写旧场景。
- 常规补载走现有网格 `Delta` 更新，不重新创建材质、贴图或 Cycles Session。状态列区分“首用时载入 / 加载中 / 已就绪 / 加载失败”，保留“部分支持”提示；读取失败可以点击“重试加载”。
- “刷新参数目录”重新发现选中对象及穿戴物、骨骼附件的参数，按稳定身份保留输入、姿势和暂存值。新增、替换文件可以被发现；追加进来的对象使用各自原始 DUF。基础几何资产版本变化时明确要求重新打开场景，避免套用旧顶点索引。
- 勾选“手动应用参数”后，可以暂存多项修改，再点击“应用”统一提交；目录刷新、相机和材质操作不会提前提交暂存值。取消勾选会应用暂存项。

## 加载与内存结构

`daz/documents` 提供不可变文档视图、批量文件读取和带版本的 CBOR 元数据缓存。SAX 扫描仍校验 JSON 语法与差值条目数量，但跳过几何、UV、差值等大型数组的 DOM 构造；完整差值的数值、范围和重复顶点检查留到首用时。

缓存默认位于 `%LOCALAPPDATA%/DazFastViewer/cache/metadata-v2`，可用 `DFV_ASSET_CACHE` 指定独立测试目录。键包含规范化路径、视图类型、文件大小和修改时间，缓存格式版本在目录中隔离。坏缓存回退源文件，写入失败不影响加载；更新同一路径会原子替换缓存。根目录顺序和目录枚举每次仍按当前配置执行，缓存不固定旧的资源优先级。

元数据内存缓存使用约 192 MiB 的估算预算与常数时间 LRU 淘汰。差值驻留缓存预算为 512 MiB；当前求值持有的缓冲区不会淘汰，因此活动形态本身超过预算时允许超出。元数据预取与差值读取各最多 4 个工作线程，不为每个参数创建线程。

此外，移除了大型 JSON 子树复制，使用连续顶点标记进行校验，复用同一身体的 Fit To 表面索引，并用固定栈查询最近表面，减少反复分配。公式地址和依赖恢复结果也复用，避免重复解析相同引用。

## 验证口径

CPU 诊断包含几何 / 材质、参数发现、骨架、公式编译、报告、首次形变与拾取索引；不包含 Qt、Cycles 和 GPU 首帧。编辑器首帧另行通过副屏正常加载与显示事件测量。冷缓存指本程序的元数据缓存为空，不表示清空 Windows 文件缓存；各数字是本机单次样本，不能把不同运行中的阶段时间相加。

完整差值路径保留在诊断工具的 `--eager` 选项中，用于与按需路径核对所有首次形变顶点和有效权重。正常编辑器使用按需路径。

## 本机实测

独立 CPU 诊断的缓存命中样本从 **424.969 秒降至 100.644 秒**，用时减少约 **76.3%**；峰值工作集从 **3.889 GiB 降至 1.460 GiB**。原始和优化后分别是独立进程，原始实现没有这层持久元数据缓存。

| CPU 阶段 | 原实现 / 秒 | 优化后，元数据缓存命中 / 秒 |
|---|---:|---:|
| 几何与材质 | 53.909 | 24.374 |
| Morph 目录及资源准备 | 324.679 | 41.562 |
| 骨架与保存姿势 | 10.845 | 5.810 |
| 公式编译 | 0.736 | 0.839 |
| 报告与载入临时数据释放 | 0.548 | 0.577 |
| 快照、场景复制、部位索引 | 0.289 | 0.307 |
| 构造形变运行时、Fit To 绑定等 | 16.502 | 5.485 |
| 首次形变（含此时补载所需差值） | 17.332 | 21.548 |
| 拾取索引 | 0.128 | 0.141 |

首次形变阶段现在包含此前提前完成的差值读取，所以该阶段本身未缩短；整体准备工作已明显减少。初始只加载了 **6,409 份唯一差值资源中的 312 份**，驻留差值 **24,541,744 字节，约 23.4 MiB**，原来各实例保存的差值数组合计约 **1.66 GiB**。完整参数目录未被裁剪。

正常编辑器在空元数据缓存下的第一帧从 **368.523 秒降至 183.478 秒**；其中文档交接从 **322.946 秒降至 148.877 秒**。后续的形变、Cycles/GPU 准备与首次显示合计约 **34.601 秒**，这部分不能全部归为 GPU 耗时。

默认缓存目录命中时，正常编辑器首帧进一步降至 **127.688 秒**，相对原实现用时减少约 **65.4%**；文档交接为 **98.901 秒**，其后首次显示约 **28.786 秒**。该轮显示验证同样通过，见[缓存命中事件](../artifacts/load-profile/scene3-release-ui-warm/events.csv)和[界面报告](../artifacts/load-profile/scene3-release-ui-warm/editor-check.json)。因此当前仍需约两分钟，尚未达到瞬时打开；CPU 目录处理、几何与碰撞，以及渲染准备仍是下一轮可测量的优化方向。

首帧使用正常窗口与当前停靠布局，基线视口是 `960×894`，新版这轮为 `840×894`，因此这项是实际使用对比而非完全同尺寸的渲染微基准。独立 CPU 阶段测量不受视口尺寸影响。

证据：原始 [CPU 诊断](../artifacts/load-profile/scene3-baseline/profile.json)、新版 [CPU 诊断](../artifacts/load-profile/scene3-release-warm/profile.json)、[冷缓存显示事件](../artifacts/load-profile/scene3-release-ui-cold/events.csv)、[真实场景显示验证](../artifacts/load-profile/scene3-release-ui-cold/editor-check.json)。

## 当前边界

- 第一次建立索引仍要读入并扫描压缩 DSF。元数据缓存不是预打包的整个场景二进制缓存；首次打开仍明显慢于缓存命中。
- 本轮未改变碰撞、平滑、蒙皮和 Cycles 的算法结果，也没有跳过不可见依赖或关闭服装碰撞以缩短首帧。剩余的碰撞和 GPU 准备仍会占用时间。
- 常规 Morph 编辑只补载数据并增量求值。目录刷新会重编译相关公式图，同时重建 CPU 求值器；现阶段大场景的 Fit To 和碰撞仍可能使刷新后的首次提交耗时。Cycles Session 和未变化网格上传可以保留，这还不是所有 CPU 阶段都严格局部化的热更新。
- 源文件变化按大小与修改时间识别；外部工具若同时刻意保持这两项不变，需要关闭编辑器、清除相应缓存后重新打开。HD、dForce、复杂 TriAx 等既有支持边界不因本轮优化而扩大。

## 复现

`tools/build.ps1` 构建编辑器并执行 11 项 CTest，包括新增 `lazy_morph` 专项测试。`SceneLoadProfile` 是额外的可选诊断目标。

```powershell
$env:DFV_ASSET_CACHE = 'D:/Github/DazFastViewer/artifacts/my-load-cache'
./build/Release/SceneLoadProfile.exe 'H:/G1/Scenes/3.duf' './DazFastViewer.project.json' './artifacts/my-load-profile'
# 相同命令换输出目录再次执行，测本程序元数据缓存命中。
# 末尾加 --eager 可核对完整差值路径。

python tools/make_lazy_fixture.py artifacts/lazy-fixture
./out/DazFastViewer.exe --file artifacts/lazy-fixture/scene.duf --project artifacts/lazy-fixture/project.json --lazy-test --output artifacts/lazy-ui
```

界面自动验证始终运行在第二屏。测试夹具独立生成，不写入用户内容库。
