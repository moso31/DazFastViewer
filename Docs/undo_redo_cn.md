# 撤销、重做与异常恢复

## 使用

- 菜单“编辑 → 撤销／重做”，会显示将要恢复的操作名称。
- 顶部独立的“撤销／重做模块”提供左回转、右回转箭头按钮，悬停显示操作名称与快捷键；没有可恢复的操作时置灰。该组和其他顶部工具组一样，可移动、浮动、隐藏并保存布局。
- 撤销：`Ctrl+Z`；重做：`Ctrl+Y` 或 `Ctrl+Shift+Z`，支持原生 3D 视口。
- “项目 → 项目设置 → 资源与保存 → 保存文件”中的“撤销历史上限”默认 50，可设为 1–500。“应用”立即改变本会话上限，“保存”同时写入项目配置 `history_limit`。
- 一次滑块拖动、数值按钮长按、键盘连续步进，计为一条；同一数值控件连续滚轮在停顿 400 毫秒后收束。输入文字在提交数值时计入。
- 拖动中按 Esc 取消本次修改；此时撤销也先取消未提交的交互。已提交后，撤销回到整个操作前。无变化、取消和失败的编辑不占历史，也不丢弃已有重做分支。
- 撤销后提交新的编辑会清除旧重做分支。历史超过上限时淘汰最早的操作。

## 覆盖范围

| 功能 | 恢复内容与操作边界 |
| --- | --- |
| 打开、追加、穿戴资源 | 整个导入结果作为一条；包含新增对象、材质、绑定与参数。失败的后台加载不入栈 |
| 新建／替换场景 | 可撤销回旧场景，恢复旧场景保存目标；支持继续重做进入新场景 |
| 删除、解除／重新绑定附件 | 恢复对象及连带的服装、头发、骨架关系、参数、材质和选择 |
| 对象变换、显隐、Gizmo | 位移、旋转、分轴／整体缩放、显隐；Gizmo 一次拖动一条 |
| Morph、参数恢复、目录刷新 | 原始输入、越界状态、目录身份；不把 ERC/JCM 计算结果作为另一个编辑 |
| 手动应用 | 未应用输入与此前已应用值一起恢复；“应用暂存参数”及关闭手动模式时的应用各为完整操作 |
| FK、IK、PowerPose | 受本次操作影响的整条姿势链、角色变换；一次拖动一条；恢复姿势、位置／角度固定也进入历史 |
| 生长、密度、重量 | 扩展启用、年龄／步长／密度等参数，以及联动 Morph、缩放与位移，一次用户操作一条 |
| 地面对齐 | 对齐比例、实际位移、普通对象及 DAZ Instance 的独立偏移 |
| SubD | 对象使用的细分等级 |
| 灯光 | 新建、删除、变换、功率等现有可编辑状态 |
| 材质 | 数字、颜色、开关、枚举、贴图、单项／表面恢复；多表面修改合并为一条；DUF 材质与所选表面预设也包含在内 |
| 姿势／形态／组合预设 | 一次应用的完整变化 |
| 场景环境与色调 | 参数调整及设置文件载入 |
| 参数收藏 | 随场景保存的参数收藏状态 |

相机旋转、平移、缩放、WASDQE、单手导航、F／侧键聚焦、框选观察不进入历史。对象／骨骼／表面选择作为操作上下文恢复，单独选择不增加历史。搜索、展开折叠、工具模式、布局、应用设置、项目设置和近期使用管理不进入历史。

保存／另存为不是可撤销操作，也不会撤销已写入磁盘的文件。同一场景内撤销普通编辑保持最近选择的保存路径；跨新建／替换场景时恢复对应场景的路径。保存会标记历史保存点，标题星号反映是否处于该保存点。

## 自动保存与异常恢复

编辑提交、撤销、重做后，将最新状态交给后台写入。正常关闭会提交当前数值输入、等待最终状态落盘，并写入正常退出标记。启动时若发现同一项目存在异常中断的会话，提示“上次程序未正常退出。是否恢复最后一次操作记录？”；选择恢复后重建场景和暂存参数，选择不恢复则将该候选标记为已忽略。

文件位于 `QStandardPaths::AppLocalDataLocation/recovery/<项目路径哈希>/session-<UUID>.json`。格式为 `dfv-recovery` 版本 1，内部复用 DUFEX 场景描述，补充原始 Morph 输入、手动模式、未应用值、选择上下文、内容库路径和保存目标。它是独立恢复文件，不覆盖源 DUF 或用户保存的 DUFEX。

- 使用 `QSaveFile` 原子替换，失败保留上一份有效文件；连续写入请求合并，旧任务不会覆盖新状态。
- 使用每会话独立文件及进程锁；运行中的其他窗口不会被误判为崩溃。异常终止留下的锁可通过进程存活检查识别。
- 正常退出保留本次最终文件，清理较早的正常退出文件；未恢复或恢复失败的异常文件保留。
- 恢复成功且新会话恢复点写入成功后，才标记旧候选已处理。
- **恢复的是最后成功写入的场景状态；撤销／重做队列仅在当前进程中保留。** 极端断电或进程在写入前被终止时，最后一次尚未落盘的编辑可能不在恢复点内。相机和窗口布局不属于此恢复文件。
- 恢复描述引用原始模型、贴图、Morph 和预设文件；它不打包内容库。依赖资源被移动／删除而导致恢复失败时，保留恢复文件并在状态栏报告原因。

## 新功能如何接入

核心在 `src/editor/edit_history.h/.cpp`，采用统一事务入口、前后状态命令和 `QUndoStack`。界面桥接在 `history_ui.inl`，恢复文件独立于历史队列位于 `recovery.h/.cpp`。

普通同步编辑在修改前创建事务，在同一作用域内完成校验、状态变更及渲染提交：

```cpp
auto edit = history_edit(QStringLiteral("操作名称"));
// 校验输入，修改 snapshot_，按需 send()。
```

独立组件通过回调交给编辑器，例如材质面板的 `edit_requested(name, change)`；不要直接操作 `QUndoStack`。`EditHistory::execute(name, change)` 可用于非 Editor 调用方。嵌套事务只记录最外层，便于一个生长操作同时修改多个 Morph、缩放和位置。

接入时遵循以下约定：

1. **状态是事实来源。** 可编辑值加入 `Snapshot` 或 `EditState`；增加相应比较及恢复序列化。派生网格、ERC、GPU 数据通过恢复后的状态重新计算，不单独入栈。
2. **文档结构保持不可变。** 添加／删除对象、材质预设、绑定及目录变更时先创建候选 `Document`，成功后替换引用。不得原地修改历史持有的文档。参数命令只保留发生变化的对象和骨架参数；结构命令共享对应版本文档。
3. **异步工作成功后提交。** 后台解析与验证完毕后，在 UI 线程的成功回调中创建事务并发布结果。禁止把跨线程或跨事件循环的 RAII 事务悬挂在栈上；校验任务代次，过期结果不应修改当前场景。
4. **定义交互边界。** 数值滑动接入 `history_interaction(true/false, key)`，独立组件可使用 `begin_gesture/finish_gesture/cancel_gesture`。切换选择、保存及开始结构操作前结束交互。不要每帧推送命令。
5. **恢复时不再次记录。** 引擎重放与 UI 同步有抑制标记，控件同步继续使用 `QSignalBlocker`。运行时文档代次和编辑 revision 前进，旧视口提交不能覆盖撤销后的结果。
6. **身份使用稳定 ID。** 对象、骨架、关节及材质表面按 ID 关联，避免删除／追加后下标错配。选择上下文单独保存，不计作编辑。
7. **失败先保持原状态。** 优先在候选副本上校验；异常离开最外层事务时会恢复操作前状态。内部捕获异常的操作应自行避免部分提交。
8. **新增序列化必须可往返。** 持久化字段加入 DUFEX 或恢复补充字段，升级格式时明确兼容规则。回归应检查撤销、重做、取消／无变化、保存恢复，不能只检查栈条数。

历史条数限制不等同于内存字节限制。普通参数命令不复制网格；导入、删除、绑定等结构操作会保留对应文档版本，复杂场景仍可能占用较多 CPU 内存，淘汰命令后释放无引用的版本。

## 验证入口

- `tools/build.ps1`：完整构建、工程 CTest 和运行文件部署，包含 `edit_history`。
- `tests/edit_history.cpp`：状态往返、连续操作合并、取消、分支、上限动态调整、保存点、跨场景、实际 Qt 控件、多表面编辑、恢复点原子写入、进程锁、真实异常退出子进程、暂存参数与空场景恢复。
- `tests/project_settings.cpp`：默认上限、存取、非法配置及实际设置控件。
- `DazFastViewer.exe --self-test --history-test --file <测试场景> --project <测试项目> --output <证据目录>`：实际编辑器、Renderer、原生快捷键、各场景修改入口、过期姿势提交拒绝、跨场景以及相机保持。夹具由 `tools/make_edit_regression_fixture.py` 生成。
- `--gizmo-test`：实际鼠标拖动的模型、骨骼、灯光与平面变换，额外检查每次提交只有一条历史、撤销／重做恢复一致、取消不入栈。

本轮证据保存在 `artifacts/history/` 及 `artifacts/history-*.log`，不写入用户资源库。
