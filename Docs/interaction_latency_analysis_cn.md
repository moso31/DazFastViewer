# 视口等待与角色移动卡顿分析

日期：2026-09-23。007 后诊断，008 未开始。本轮完成内容浏览器紧凑布局和视口 guide 移除；以下为现有实现与用户最近会话的诊断，尚未实施渲染优化。

## 结论

有明确的优化空间。相机或角色移动后重新累计光照是当前路径追踪器的正常行为；这不要求重新加载 DUF，也不要求每次重建全部材质、纹理和几何。需要分别处理视口尺寸改变、相机导航、对象刚性移动和 Morph / 姿势形变。

现有实现已使用动态 BVH，`CyclesAdapter::apply` 也已经区分相机、实例矩阵和网格顶点更新。因此可以沿现有增量结构优化，无需推翻原设计。

同一会话中，271 次“最后一帧低清预览 → 下一帧完整分辨率”显示间隔，中位数约 116 毫秒，最大约 1.40 秒。此数值是两帧之间的间隔，**不是鼠标松开到出图延迟**，也不是收敛到无噪点的耗时。

单次 `render_work_cpu` 包围的渲染工作最长约 3.30 秒，中位数约 62 毫秒。这是渲染工作调用的经过时间，不能解释为纯 CPU 计算时间。较长的 GPU 工作批次可能影响新交互的响应，需要进一步分解取消与同步等待。

提取结果：`artifacts/interaction-latency/existing-session.json`。不能把两个相邻显示帧之间的全部空档都当作卡顿，因为用户可能没有操作，或者渲染已达到采样上限。

## 角色移动的额外开销

源码检查确认以下工作存在，但当前日志缺少逐次编辑输入和各 CPU 阶段时间，尚不能给出各项占比：

1. **没有编辑期间的低清预览。** `Renderer::run` 中的 `wanted_preview` 仅取决于相机导航。角色平移、旋转和参数滑块提交后，继续按完整分辨率进行渲染；新编辑还受上一渲染版本呈现及 `ready_to_reset()` 条件约束。
2. **实例矩阵变化也触发全场景选取 / 高亮重建。** `geometry_dirty` 同时包含 `delta.instances`。随后 `PickingScene::update` 清空并重新建立世界空间三角面树；`HoverOverlay::update` 释放并重建所有对象及部位的显示列表。这些工作与光照计算无关。
3. **刚性移动仍经过完整的求值入口。** 编辑器调用 `DeformationRuntime::prepare` 和 `evaluate`，两者都进入 `feed`，遍历参数和骨骼通道。底层有脏数据检查，不代表每次都实际重新蒙皮，但仍存在全量遍历、复制及依赖检查。
4. **碰撞复用条件偏保守。** `CollisionRuntime::evaluate` 使用相对矩阵精确比较；含 GeoGraft 的碰撞绑定还会因源对象的实例变换标记为变化。父角色与附件一起刚性移动时，可能重新建立表面索引并执行碰撞。后续需按相对形状是否真的变化判定，保留必要的碰撞与跟随语义。
5. **诊断包围盒扫描。** 变换计数变化后，渲染线程遍历所有目标的顶点和头部面来更新包围盒与位移诊断，也可按受影响对象缩小范围。

## 建议实施顺序

1. **视口 resize 保留会话和场景。** 仅更新相机、渲染尺寸和显示缓冲，安全等待并更新 GPU / OpenGL 共享缓冲，继续复用材质、纹理和加速结构；不要再因几像素变化加载整个场景。
2. **给对象拖动接入交互预览。** 拖动期间合并旧输入、优先显示最新姿态，采用低分辨率和少量样本；停止后恢复完整画质。需验证释放、失焦、手动应用参数及失败重试边界。
3. **按实例复用选取和高亮数据。** 刚性移动仅更新对象矩阵与上层包围盒；对象局部三角面结构、显示顶点和未变化对象继续复用。Morph / 蒙皮发生实际顶点变化时再更新受影响对象。
4. **细化形变与碰撞的变化标记。** 将刚性变换与 Morph / Pose 的求值路径分离；共同移动的角色和穿戴物在相对关系不变时复用碰撞结果。必须保留附件挂接、GeoGraft 和服装跟随的正确性。
5. **限制长渲染批次的交互延迟。** 测量请求到取消、场景同步和首次呈现的分段时间，调整交互调度和分辨率恢复策略。继续遵守不启用降噪的现有要求。

实施前后应使用相同的 `6.duf` 和可复现的短操作测量：输入到第一次新图、松手到完整分辨率、CPU 求值、选取 / 高亮更新、场景同步及渲染工作时间。现有日志已经能证明存在可优化的重建路径，但不足以承诺优化后的帧率或总提速倍数。
