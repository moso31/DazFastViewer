# 场景加载优化与兼容性修复

实施日期：2026-09-27 至 2026-09-28。原始测量见[大场景加载调研](large_scene_load_investigation_cn.md)。验收目标仍为保留现有模型、材质及画质，并尽量在 60 秒内出现可交互的完整场景首帧。

本轮已完成并行加载、缓存复用及已发现的加载阻塞修复，Release 已部署到 历史验证的可执行文件。**60 秒目标尚未达到**：`17.duf` 的编辑器首帧由原基线的 215.46 秒降到再次打开的 87.28 秒；独立空应用缓存为 165.40 秒。下文区分 CPU 测量、实际首帧及不同缓存条件。

## 已实施的改动

- 资源文档使用最多 4 个工作线程解析，解析结果在同一次导入的几何、参数和骨架阶段共享，完成导入后释放。共享内容带文件大小和修改时间版本检查。
- Morph 元数据以 64 个文件为一批读取，返回并保留句柄和异常；并发请求同一版本的文件合并为一次读取。LRU 淘汰的大文档在锁外销毁。
- 内嵌 Morph 使用独立差值视图，共享解析和磁盘缓存，跳过不相关的场景、几何与材质 DOM，避免对每个活动 Morph 重复解析整份大场景。
- 按独立资产分组并行建立参数目录。场景覆盖、原生通道和节点索引只处理一次；输出按原场景对象顺序合并，保留内容库优先级、实例覆盖和依赖诊断。
- Modifier 的设置按唯一资产建立小型索引，避免每个实例重新解码同一文档。路径解析在单次加载内缓存，遍历只读 JSON 数组时使用引用。
- 并行计算服装表面绑定、蒙皮顶点和渲染细分。每个顶点内部仍使用原计算顺序，场景依赖顺序不变。
- 凹凸贴图所需的面积按材质一次累计，避免每种材质都重新遍历全场景；同一张图的尺寸在一次同步中只读取一次。

## 加载失败修复

### Geometry Shell

空的 Shell 几何定义在宿主及 GeoGraft 建立后重建。保留壳层材质、面组和材质组显隐、显式 UV、Push 偏移及自己的变换，在 Morph、蒙皮、碰撞和焊接后跟随宿主控制网格。追加场景和删除宿主时维护引用。

支持顶层 Modifier 通道和 `studio_modifier_channels / Value` 两种偏移存储方式。实际 `5b.duf` 的偏移为 `0.015 cm`。

这不是完整 DAZ Studio 几何求值器的逐点等价认证；未进行 DAZ Studio 导出金标准图像比较。

### Rope 的 Local 权重

`9/1.duf` 的 Rope 有 61 个关节，三个轴和缩放图全部一致，44,064 个顶点的权重和在 1 附近。原先仅接受刚性 Local 权重的判断错误地拒绝了这类柔性权重。现在将归一化、相同轴的权重按线性蒙皮处理，保留累计刚性链的既有转换。

这不等于支持所有 TriAx：不同轴的权重图及不满足这些条件的 Local 绑定仍保留明确的能力检查。

### 无可绘制面的容器

`5b.duf` 的 `TRCBASE` 是含 4 个参考顶点、没有面的城市底座。现在允许没有面及曲线的网格没有材质槽，保留其顶点、节点和变换；有可绘制面却缺少材质的网格仍报错。

## 验证口径

- 使用原项目的四个内容库，不修改 `H:/g1` 和其他内容库。
- 应用冷缓存使用独立空 `DFV_ASSET_CACHE`，不清空 Windows 文件缓存。
- CPU 测量与编辑器首帧分别统计，不能拼接不同进程的时间作为一次完整加载。
- 回归对比包括全部网格位置哈希、有效参数权重哈希、非零参数、Morph 差值访问数和服装绑定数。
- 编辑器测试保留当前用户画质设置；首帧取 `events.csv` 的首次 `present_submitted`。

测量与构建证据保存在 `artifacts/load-optimization-20260927/`。

完整 Release 构建的 28 项 CTest 回归全部通过。新增测试覆盖 Shell 偏移的两种存储格式、面组显隐、UV、形变跟随、自身变换、追加和删除、删除插件后的派生部件清理、并发文档读取、源文件修改后的缓存失效，以及相同轴柔性权重的旋转和缩放。

## CPU 实测及数据一致性

以下为最终版本的独立 CPU 测量，包含活动 Morph 差值准备、初始形变及拾取索引，不包含 Qt、纹理上传与 GPU 场景构建。均使用已预热的应用缓存，不能当作首次打开或视口首帧成绩。

| 场景 | 原版本 CPU 时间 | 优化后 CPU 时间 | 结果 |
| --- | ---: | ---: | --- |
| `17.duf` | 164.80 秒（暖缓存） | 63.63 秒 | 耗时减少 61.4% |
| `test9.duf` | 171.47 秒（原有混合缓存） | 57.57 秒 | 原基线缓存条件不同，不能全部归因于代码优化 |
| `5b.duf` | 138.77 秒后加载失败 | 74.58 秒 | 完成加载，包含宿主和两个 GeoGraft 的 Shell 部件 |

`17.duf` 和 `test9.duf` 的全部网格位置哈希、有效参数权重哈希、非零参数数量、Morph 差值访问数、服装绑定数均与原版本一致。`5b.duf` 原版本无法完成加载，因此对比对象是本轮修复后、最后一次差值缓存优化前的成功版本；这项对照证明差值缓存优化没有改变其计算结果，不能替代 DAZ Studio 的视觉校准。

证据为 `verified-v6-Scenes-*-cpu-1/profile.json` 和 `parity-v6.json`。该 CPU 测试程序的 SHA-256 为 `24b50cfd544bfb1228adff4c4740f15188fce8c399b669e2e675d3bd34fd8f46`。

## 编辑器实测

在 Ryzen 7 5800X、64 GiB 内存、RTX 4070 Ti SUPER 16 GiB 的本机上顺序测试，期间不并行执行编译或其他场景测量。`H:` 是 USB SSD。完整场景首帧以 `present_submitted` 为准，该时刻已完成初始形变、拾取索引和渲染场景构建；不是最终降噪收敛图。

| 场景及条件 | 优化后首帧 | 结果 |
| --- | ---: | --- |
| `17.duf`，空应用缓存 | 165.40 秒 | 成功 |
| `17.duf`，同缓存再次打开 | 87.28 秒 | 成功，较原有缓存基线减少 59.5% |
| `5b.duf`，已预热资源缓存 | 79.52 秒 | 原先失败，修复后成功 |
| `9/1.duf`，已预热资源缓存 | 63.73 秒 | 原先失败，修复后成功 |
| `test9.duf`，已预热资源缓存 | 80.75 秒 | 成功 |
| `12c.duf`，已预热资源缓存 | 82.29 秒 | 成功 |

五个代表场景的六次编辑器运行均正常退出，显示检查为 `PASS`，渲染错误为空；各次用户画质参数一致。原先无法完成加载的 `5b.duf` 和 `9/1.duf` 已实际通过 GPU 构建并显示。

`17.duf` 的原基线与当前渲染统计均为 65 个实例、9,105,021 个三角形；`5b.duf` 为 2,130 个实例、6,637,106 个三角形，包含场景实例化对象。`17.duf` 再次打开的峰值工作集约 9.37 GiB，未通过减少场景内容获得提速。

画质使用原用户设置：纹理上限 1024、开启凹凸与法线、关闭 SSS 和降噪、透明反弹 16。没有为测试下调这些设置。此次用户布局下首帧渲染尺寸为 256 × 246，原基线为 267 × 250，因此不是严格相同视口尺寸的实验；单次观测也不是稳定性分位数。空应用缓存不代表 Windows 文件缓存、驱动内核缓存也为空。

只有 `17.duf` 做了同一空缓存起点的两次连续配对测试。其余场景复用了前期 CPU 测量建立的资源缓存，纹理缓存按实际已存在的内容使用，没有强制全部预热；因此这些数值是现有缓存条件下的验收结果，不代表它们各自的冷/暖配对结果。

测量目录是 `ui-cold-pair-v6-Scenes-17-ui-1/2` 和 `ui-verified-v6-*-ui-1`，汇总为 `ui-summary-v6.json`。每次保留 `run.json`、`events.csv`、资源采样、显示检查及渲染统计。编辑器 SHA-256 为 `8a4da87daf1871a7caaadd2468ca07fc26c97014243d512770221ecc34430785`；部署清单的全部源文件哈希与工作区一致。

## 距离 60 秒的剩余工作

`17.duf` 再次打开时，文档交接约在 55.94 秒，渲染会话在 69.48 秒创建，适配器构建耗时 3.38 秒，后续场景同步耗时 14.20 秒，首帧在 87.28 秒显示。首次空应用缓存的场景同步为 35.05 秒。上述时间属于同一编辑器进程的事件记录，不能与独立 CPU 测量逐项相加。

要继续接近目标，需要进一步缩短参数目录重建、完整 JSON DOM 构建和释放，以及首次纹理解码与上传。优先方向是带依赖失效校验的资产编译缓存，并将首帧必需的 Morph/公式依赖和非活动参数目录分开调度。首次打开仍需要优化源文件解析与纹理准备，不能只依靠再次打开的缓存收益。这些是后续实现方向，本轮未将其列为已完成，也未以隐藏模型、降低细分或关闭材质作为达标手段。
